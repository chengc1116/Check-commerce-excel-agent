# 产品立项审核系统 — 量化评分标准（详细逻辑）

> 总分 100 分，4 种立项类型各有不同的评分维度与权重。
> 每个维度标注了**数据来源**和**具体计算公式**。

---

## 一、🔥 爆品升级

> 适用场景：该品类已有爆品（二级品类单月销量 > 2000），通过模块升级追赶或超越爆品。

### 维度1：模块差距（30分）

**数据来源**：LLM 对比分析输出的 `module_comparison` 数组（每个元素含 `gap_level` 和 `user_perception`）

**计算公式**：

```
对每个模块:
  扣分系数 = gap_level映射(高=1.0, 中=0.6, 低=0.3, 无=0)
  感知权重 = user_perception映射(高=1.5, 中=1.0, 低=0.5)
  该模块扣分 = 扣分系数 × 感知权重

总扣分 = Σ(每个模块扣分)
最大可能扣分 = 模块数 × 1.5  (最大感知权重 × 最大差距系数)
扣分比例 = 总扣分 / 最大可能扣分

最终得分 = max(0, 30 × (1 - 扣分比例))
```

**举例**：5个模块，差距分别为[高,中,低,无,中]，感知分别为[高,中,低,中,低]
- 扣分 = 1.0×1.5 + 0.6×1.0 + 0.3×0.5 + 0×1.0 + 0.6×0.5 = 1.5+0.6+0.15+0+0.3 = 2.55
- 最大扣分 = 5 × 1.5 = 7.5
- 扣分比例 = 2.55 / 7.5 = 0.34
- 得分 = 30 × (1 - 0.34) = **19.8 → 19分**

**无数据兜底**：`module_comparison` 为空 → 10分

---

### 维度2：升级可行性（25分）

**数据来源**：LLM 对比分析输出的 `upgrade_roadmap` 数组（每个元素含 `priority` 字段：P0/P1/P2）

**计算公式**：

```
P0数量 = roadmap中priority="P0"的数量
P1数量 = roadmap中priority="P1"的数量
P2数量 = roadmap中priority="P2"的数量
P0占比 = P0数量 / 总路线图项数

P0占比 ≤ 20%  → 基础分 = 25 × 0.9 = 22.5 → 22分 (聚焦，可行性高)
P0占比 ≤ 40%  → 基础分 = 25 × 0.7 = 17.5 → 17分 (适中)
P0占比 ≤ 60%  → 基础分 = 25 × 0.5 = 12.5 → 12分 (偏多，资源分散)
P0占比 > 60%  → 基础分 = 25 × 0.3 = 7.5 → 7分  (过多，风险大)

最终得分 = 基础分 + P1调整分 + P2调整分
```

**无数据兜底**：`upgrade_roadmap` 为空 → 10分

---

### 维度3：复用基础（25分）

**数据来源**：LLM 对比分析输出的 `summary.reuse_modules` 和 `summary.new_modules_needed`

**计算公式**：

```
可复用数 = len(reuse_modules)
需新建数 = len(new_modules_needed)
总操作数 = 可复用数 + 需新建数
复用率 = 可复用数 / 总操作数

最终得分 = max(0, 25 × 复用率)
```

**举例**：可复用3个，需新建2个 → 复用率 = 3/5 = 60% → 得分 = 25 × 0.6 = **15分**

**无数据兜底**：两者都为空 → 12分

---

### 维度4：市场匹配度（20分）

**数据来源**：数据库查询的 `hot_products`（爆品列表，含 `avg_sales`）+ `market_overview`（品类市场概况，含 `total_category_sales`）

**计算公式**：

```
Step 1 — 基于爆品销量定基础分:
  有爆品:
    头部爆品月均销量 ≥ 5000  → 18分
    头部爆品月均销量 ≥ 2000  → 14分
    头部爆品月均销量 < 2000  → 10分
  无爆品:
    → 6分

Step 2 — 品类市场成熟度加成:
  品类总销量 ≥ 50000  → +2分 (上限20分)
```

**举例**：头部爆品月均3500，品类总销量60000 → 14 + 2 = **16分**

## 二、⚔️ 竞品升级

> 适用场景：对标具体竞品产品，通过复制竞品卖点 + 差异化超越来升级我方产品。

### 维度1：竞品理解度（25分）

**数据来源**：VL 模型拆解竞品图片输出的 `competitor_product.modules`（每个模块含 `confidence` 字段）

**计算公式**：

```
总模块数 = len(competitor_product.modules)
高置信数 = modules中confidence="high"的数量
中置信数 = modules中confidence="medium"的数量

置信度得分 = (高置信数 × 1.0 + 中置信数 × 0.6) / 总模块数

最终得分 = max(5, int(25 × 置信度得分))
```

**举例**：拆解8个模块，5个high、2个medium、1个low
- 置信度得分 = (5×1.0 + 2×0.6) / 8 = 6.2/8 = 0.775
- 得分 = 25 × 0.775 = **19分**

**无数据兜底**：无竞品模块拆解 → 5分

---

### 维度2：差异化空间（25分）

**数据来源**：LLM 对比分析输出的 `module_comparison` 数组（每个元素含 `strategy` 字段）

**计算公式**：

```
可超越/复制数 = module_comparison中strategy为"超越"或"复制"的数量
总对比模块数 = len(module_comparison)
超越复制占比 = 可超越/复制数 / 总对比模块数

最终得分 = max(5, int(25 × min(1.0, 超越复制占比 × 1.5)))
```

**举例**：6个对比模块中，3个"超越"+1个"复制"= 4个
- 占比 = 4/6 = 66.7%
- 加成后 = 66.7% × 1.5 = 100%（封顶1.0）
- 得分 = 25 × 1.0 = **25分**

**无数据兜底**：无模块对比数据 → 8分

---

### 维度3：复制可行性（25分）

**数据来源**：同爆品升级的复用基础，取 `summary.reuse_modules` 和 `summary.new_modules_needed`

**计算公式**：同爆品升级维度3

```
复用率 = 可复用数 / (可复用数 + 需新建数)
最终得分 = max(0, 25 × 复用率)
```

---

### 维度4：超越潜力（25分）

**数据来源**：LLM 对比分析输出的 `summary.surpass_modules`（可差异化超越的模块列表）

**计算公式**：

```
有超越模块:
  最终得分 = min(25, 10 + len(surpass_modules) × 5)
无超越模块:
  最终得分 = 8
```

**举例**：识别到3个可超越模块 → 10 + 3×5 = **25分**（封顶）

---

## 三、📉 未起量迭代

> 适用场景：品类下产品销量均未起量（单月销量 < 500），需要迭代升级寻找起量突破口。

### 维度1：迭代方向清晰度（25分）

**数据来源**：同爆品升级的升级可行性，取 `upgrade_roadmap`

**计算公式**：同爆品升级维度2

```
P0占比 ≤ 20%  → 25 × 0.9 = 22分
P0占比 ≤ 40%  → 25 × 0.7 = 17分
P0占比 ≤ 60%  → 25 × 0.5 = 12分
P0占比 > 60%  → 25 × 0.3 = 7分
```

---

### 维度2：可复用基础（25分）

**数据来源**：`summary.reuse_modules` + `summary.new_modules_needed`

**计算公式**：同爆品升级维度3

```
复用率 = 可复用数 / (可复用数 + 需新建数)
最终得分 = max(0, 25 × 复用率)
```

---

### 维度3：增量空间（25分）

**数据来源**：LLM 对比分析输出的 `module_comparison`（含 `gap_level` 字段）

**计算公式**：

```
差距模块数 = module_comparison中gap_level为"高"或"中"的数量
总对比模块数 = len(module_comparison)
差距占比 = 差距模块数 / 总对比模块数

差距占比 20%~60%  → 20分 (最佳区间：有增量空间但不过度)
差距占比 < 20%    → 12分 (差距太小，增量有限)
差距占比 > 60%    → 10分 (差距过大，补齐成本高)
```

**举例**：8个对比模块中3个高差距+1个中差距=4个
- 差距占比 = 4/8 = 50%，落在20%~60%区间 → **20分**

**无数据兜底**：无模块对比数据 → 8分

---

### 维度4：风险可控度（25分）

**数据来源**：`summary.reuse_modules` + `summary.new_modules_needed` + 数据库查询的 `launched_products`（已起量产品列表）

**计算公式**：

```
Step 1 — 基于新建占比:
  新建占比 = 需新建数 / (需新建数 + 可复用数)
  基础分 = max(5, int(25 × (1 - 新建占比 × 0.8)))

Step 2 — 已起量产品风险扣减:
  如果存在已起量产品(launched_products):
    最终得分 = max(5, 基础分 - 5)
  否则:
    最终得分 = 基础分
```

**举例**：可复用4个、需新建1个 → 新建占比 = 1/5 = 20%
- 基础分 = 25 × (1 - 0.2 × 0.8) = 25 × 0.84 = **21分**
- 若有2个已起量产品 → 21 - 5 = **16分**

**无数据兜底**：无操作数据 → 10分

## 四、🗺️ 品类地图缺失

> 适用场景：我方品牌在该品类下没有产品或产品不足，属于品类空白或品类补全。
> 三种缺失类型：
> - **完全品类缺失**：整个品类没有任何品牌有产品（市场未被验证，机会与风险并存）
> - **半品类缺失**：别的品牌有产品，但我方品牌没有（市场已被验证，机会最大）
> - **品类补全**：同品牌下已有产品（只是补充产品线）

### 维度1：市场机会（35分）

**数据来源**：数据库查询的 `gap_info.has_gap`（是否品类空白）+ `market_overview.brand_distribution`（品牌分布，判断其他品牌是否有产品）+ `competitor_product.modules`（竞品模块拆解）+ `category_sales_summary.total_sales`（品类总销量）

**计算公式**：

```
Step 1 — 品类缺失程度基础分（三分法）:
  完全品类空白（has_gap=True 且 无其他品牌）→ 20分 (市场未被验证)
  半品类缺失（has_gap=True 但 有其他品牌）  → 25分 (市场已被验证，机会最大)
  品类补全（has_gap=False，同品牌已有产品） → 10分 (只是补充)

Step 2 — 竞品验证加成:
  有竞品模块拆解数据           → +5分 (上限35)

Step 3 — 市场成熟度加成:
  品类总销量 ≥ 50000          → +3分 (上限35)
  品类总销量 ≥ 10000          → +1分 (上限35)
```

**举例**：半品类缺失（3个其他品牌有产品）+ 有竞品验证 + 品类总销量60000
- 25 + 5 + 3 = **33分**

**举例**：完全品类空白 + 有竞品验证 + 品类总销量12000
- 20 + 5 + 1 = **26分**

**举例**：品类补全（已有3个同品牌产品）+ 有竞品验证
- 10 + 5 = **15分**

---

### 维度2：模块复用度（25分）

**数据来源**：`summary.reuse_modules` + `summary.new_modules_needed` + `competitor_product.modules` + `gap_type`（缺失类型判断）

**计算公式**（区分缺失类型）：

#### 完全品类缺失（从未做过这个产品）

```
情况A: 无任何模块数据（reuse_modules 和 new_modules_needed 都为空）
  且无竞品拆解   → 5分  (完全找不到类似品，复用极低)
  且有竞品拆解   → 10分 (有竞品参考但复用数据不完整)

情况B: 有模块数据
  复用率 ≥ 50%  → 18分 (工厂有该品类的模块，可以复用)
  复用率 < 50%  → max(3, int(25 × 复用率 × 0.6)) (基础薄弱)
```

**举例**：完全品类缺失，工厂有3个可复用模块，需新建2个 → 复用率 60% ≥ 50% → **18分**

**举例**：完全品类缺失，无模块数据，无竞品拆解 → **5分**

#### 半品类缺失 / 品类补全

```
正常复用率计算:
  复用率 = 可复用数 / (可复用数 + 需新建数)
  最终得分 = max(0, 25 × 复用率)
```

**举例**：半品类缺失，可复用3个、需新建2个 → 复用率 60% → 25 × 0.6 = **15分**

---

### 维度3：进入门槛（25分）

**数据来源**：`summary.reuse_modules` + `summary.new_modules_needed`

**计算公式**：

```
Step 1 — 按模块类型加权计算新建占比:
  面料/版型类模块权重 = 1.5（面料可以更好，门槛更高）
  其他模块权重 = 1.0

  对每个"需新建"模块: 判断是否为面料/版型类
    weighted_new += 1.5 (面料/版型) 或 1.0 (其他)
  对每个"可复用"模块: 同样判断
    weighted_total += 1.5 (面料/版型) 或 1.0 (其他)
  weighted_total = weighted_new + weighted_可复用

  加权新建比 = weighted_new / weighted_total

Step 2 — 计算得分:
  最终得分 = max(5, int(25 × (1 - 加权新建比 × 0.7)))

Step 3 — 工厂能力加成:
  如果是完全品类缺失但有可复用模块（工厂有相关产品可做）
  或 LLM 输出了 factory_capability 信息
    → +3分 (上限25)
```

**面料/版型关键词**：面料、版型、布料、材质、织物、内衬、外层、包布

**举例**：需新建3个模块（其中1个是面料类），可复用2个模块
- weighted_new = 1×1.5 + 2×1.0 = 3.5
- weighted_可复用 = 2×1.0 = 2.0
- weighted_total = 3.5 + 2.0 = 5.5
- 加权新建比 = 3.5/5.5 = 63.6%
- 得分 = 25 × (1 - 0.636 × 0.7) = 25 × 0.555 = **13分**
- 若工厂有相关产品 → 13 + 3 = **16分**

**无数据兜底**：无操作数据 → 10分

---

### 维度4：价格竞争力（15分）

**数据来源**：`summary.pricing`（我方定价）+ `summary.erp_price`（ERP成本价）+ `summary.competitor_price`（竞品价格）或 `module_comparison[].competitor_price`

**计算公式**：

```
前提: 须同时有我方定价和竞品价格，否则走兜底逻辑

Step 1 — 计算价格偏差率:
  偏差率 = (我方定价 - 竞品价格) / 竞品价格

Step 2 — 基于偏差率评分:
  偏差率 -10%~+10%   → 15分 (价格接近，竞争力强)
  偏差率 -20%~-10%   → 12分 (略低于竞品，性价比路线)
  偏差率 +10%~+20%   → 10分 (略高于竞品，需差异化支撑)
  偏差率 -30%~-20%   → 8分  (偏低较多)
  偏差率 +20%~+30%   → 6分  (偏高较多)
  偏差率 > +30%       → 3分  (过高)
  偏差率 < -30%       → 5分  (过低)

Step 3 — 毛利空间扣减:
  如果有 ERP 成本价:
    毛利率 = (我方定价 - ERP成本价) / 我方定价
    毛利率 < 20%  → -3分 (毛利不足)
    毛利率 < 40%  → -1分 (毛利偏紧)

最终得分 = max(3, min(15, Step2得分 + Step3调整))
```

**无数据兜底**：

| 缺失情况 | 兜底分 | 说明 |
|---|---|---|
| 有我方定价，无竞品价格 | 8分 | 无法对比 |
| 有竞品价格，无我方定价 | 6分 | 连定价都没有 |
| 两者都没有 | 5分 | 价格信息严重缺失 |

**⚠️ 数据前置条件**：
- 我方定价从 `summary.pricing` 获取（LLM 可能从项目书中提取）
- 竞品价格从 `summary.competitor_price` 或 `module_comparison` 中提取
- 当前**竞品价格字段可能缺失**，需在 Excel 解析或 LLM Prompt 中补充提取

## 共用计算函数汇总

### calc_gap_score（模块差距评分）

用于：🔥爆品升级 维度1

| 输入 | 来源 |
|---|---|
| `module_comparison[].gap_level` | LLM 对比分析输出 |
| `module_comparison[].user_perception` | LLM 对比分析输出 |

| 差距等级 | 扣分系数 |
|---|---|
| 无 | 0 |
| 低 | 0.3 |
| 中 | 0.6 |
| 高 | 1.0 |

| 感知等级 | 权重乘数 |
|---|---|
| 低 | ×0.5 |
| 中 | ×1.0 |
| 高 | ×1.5 |

公式：`得分 = max_score × (1 - Σ(扣分系数×感知权重) / (模块数×1.5))`

---

### calc_roadmap_score（升级路线图评分）

用于：🔥爆品升级 维度2、📉未起量迭代 维度1

| 输入 | 来源 |
|---|---|
| `upgrade_roadmap[].priority` | LLM 对比分析输出 |

| P0 占比 | 得分比例 |
|---|---|
| ≤ 20% | max_score × 90% |
| ≤ 40% | max_score × 70% |
| ≤ 60% | max_score × 50% |
| > 60% | max_score × 30% |

额外有 P1/P2 调整分（少量加成）。

---

### calc_reuse_score（复用率评分）

用于：🔥爆品升级 维度3、⚔️竞品升级 维度3、📉未起量迭代 维度2、🗺️品类缺失 维度2

| 输入 | 来源 |
|---|---|
| `summary.reuse_modules` | LLM 对比分析输出 |
| `summary.new_modules_needed` | LLM 对比分析输出 |

公式：`得分 = max_score × (可复用数 / (可复用数 + 需新建数))`

> **注意**：🗺️品类缺失的维度2（模块复用度）不再使用此函数，而是根据缺失类型（完全/半/补全）分别计算。
